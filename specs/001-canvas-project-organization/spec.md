# Feature Specification: 素材组织、可复用参考与分层 Canvas

**Feature Branch**: `codex/canvas-project-organization`

**Created**: 2026-10-19

**Status**: Draft — awaiting specification review

**Input**: User description: "装一下spec-kit，然后按照spec-kit的流程来继续开发上述功能"。
上述功能指 Assets 文件夹、Elements 共享参考、按镜头展开的 Canvas、版本收纳及工作流模板。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 先看镜头，再展开制作过程 (Priority: P1)

作为创作者，我希望打开复杂项目时先看到镜头、共享参考、声音、包装和时间线入口，
只在处理某个镜头时展开构图、生成和采用结果，避免候选与旧版本淹没主画布。

**Why this priority**: 当前痛点是百余张卡片和跨镜头连线同时出现，遮住了实际制作结构。
仅建立素材文件夹不能解决主画布的阅读问题。

**Independent Test**: 在一个含八个镜头、至少 140 张卡片的隔离示例中建立八个镜头组，
折叠后查看项目总览，展开任意镜头并再次打开项目；过程中素材与剪辑采用保持原样。

**Acceptance Scenarios**:

1. **Given** 已有任意画布，**When** 用户选择相关节点建立并命名镜头组，
   **Then** 可折叠为一个入口，并显示组名、成员数和当前结果入口。
2. **Given** 镜头组已折叠，**When** 用户展开它，**Then** 恢复成员、内部位置和局部连接；
   该镜头用到的外部共享参考可定位，不必展开其他镜头。
3. **Given** 同一生成对象有多个 take，**When** 用户查看当前制作链，
   **Then** 可收起历史结果，仍能打开版本历史并定位当前剪辑实际采用的旧 take。
4. **Given** 一个素材被多个镜头引用，**When** 折叠或移除某个分组，
   **Then** 其他镜头和真实素材仍有效；移除分组只解除组织关系。
5. **Given** 已有时间线，**When** 查看时间线使用的素材，**Then** 可看到精确采用片段，
   无需创建批量连接二十个素材的说明节点。

### User Story 2 - 用文件夹整理素材 (Priority: P2)

作为创作者，我希望在项目素材库中建立文件夹、整理与查找媒体，文件整理不改变影片内容。

**Why this priority**: 候选、原始文件与采用结果需要完整保留，又不能都占据主画布。

**Independent Test**: 创建两层文件夹，将多份已有素材批量移入、检索、移回，再移除文件夹；
刷新后目录一致，原素材仍能在画布和时间线使用。

**Acceptance Scenarios**:

1. **Given** 旧项目没有目录，**When** 打开素材库，**Then** 原有素材完整可见，并有未分类入口。
2. **Given** 用户选择多份素材，**When** 移入指定文件夹，**Then** 更新逻辑归属，
   保留素材标识、实际文件、原生成记录及其他使用位置。
3. **Given** 目录中含素材或子目录，**When** 移除该目录，**Then** 先预览受影响内容；
   确认后内容回到上一级或未分类，不删除媒体文件。
4. **Given** 用户按名称检索，**When** 切换当前目录与全项目范围，
   **Then** 结果范围明确，且能定位到素材所在目录。

### User Story 3 - 给共享参考一个稳定入口 (Priority: P2)

作为创作者，我希望把已选角色、场景、道具或声音保存为命名参考，多个镜头复用同一入口，
同时能确认本次生成实际使用了哪一版本。

**Why this priority**: 共享身份和场景是跨镜头一致性的基础；减少重复放置也能减少连线。

**Independent Test**: 从已存在素材建立一个角色参考，在两个镜头中选择它；
增加新参考版本后，核对旧生成输入和旧剪辑都没有变化。

**Acceptance Scenarios**:

1. **Given** 项目内已有图片或音频素材，**When** 保存为命名参考，
   **Then** 可填写名称、用途、说明，并定位它引用的具体素材版本。
2. **Given** 镜头选择共享参考，**When** 准备生成，**Then** 能核对实际输入素材与顺序；
   仅有显示连线不视为已送入模型。
3. **Given** 已使用的参考新增版本，**When** 用户将新版本设为当前参考，
   **Then** 标记相关制作配置待复核，保留原生成、已采用片段和历史输入。
4. **Given** 删除一个共享参考入口，**When** 它仍有使用者，
   **Then** 说明影响并要求先解除或替换引用，不能产生悬空引用或删除源素材。

### User Story 4 - 复用镜头制作流程 (Priority: P3)

作为创作者，我希望把一组制作步骤保存为模板，在另一镜头或项目中复用结构，
然后选择该镜头自己的参考和参数，不重新搭建相同流程。

**Why this priority**: 模板能减少重复搭建，但必须建立在清晰的素材、参考和版本语义上。

**Independent Test**: 保存一个“文字说明—构图—视频生成”的流程模板，实例化两次；
分别绑定不同素材，核对对象彼此独立，且没有自动生成任务。

**Acceptance Scenarios**:

1. **Given** 用户选中制作节点，**When** 保存模板，**Then** 可预览将保存的步骤、
   连接、布局、提示词和参数，以及需要重新绑定的素材位置。
2. **Given** 模板在另一个镜头实例化，**When** 用户完成参考绑定，
   **Then** 创建新的制作对象，不复制原任务标识、旧输出、旧时间线或隐藏凭据。
3. **Given** 部分参考尚未绑定或模型不可用，**When** 查看新流程，
   **Then** 明确标出待补项，允许编辑；不能悄悄借用其他项目的素材或提交生成。

### Edge Cases

- 一个节点只属于一个直接分组；多个镜头可引用同一共享参考，但不复制其源媒体。
- 镜头组第一版不支持嵌套，素材文件夹支持嵌套且不允许循环或移入自身子目录。
- 折叠成员被其他组引用时显示组间关系或按需定位；不为每条成员引用绘制平行长线。
- 有生成任务运行时可以浏览和整理；整理不取消任务、不修改已提交输入、不隐藏运行状态。
- 项目导入缺少文件、旧 take 未审、参考素材失效或模型不存在时，显示可定位的待处理状态。
- 多个窗口或 Agent 同时修改相同组织信息时，保留未提交编辑并报告冲突，不能静默覆盖。
- 组内删除节点、移除分组、删除文件夹和删除源媒体必须是不同操作，影响范围可辨认。
- 模板中出现项目素材、外部地址或本机路径时，实例化要求显式绑定项目内素材；
  模板不内嵌媒体、认证信息、历史任务记录或可执行脚本。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持命名、重命名、折叠、展开和解除镜头分组，并保留成员与布局。
- **FR-002**: 系统 MUST 区分分组入口、媒体节点和生成节点；组织入口不能被误当模型输入。
- **FR-003**: 系统 MUST 提供收起历史结果的查看方式，并能随时恢复查看全部 take。
- **FR-004**: 系统 MUST 区分当前展示结果、当前参考版本、剪辑采用结果和人工审核状态。
- **FR-005**: 系统 MUST 在选中镜头时显示相关共享引用；总览避免重复绘制成员级跨组长线。
- **FR-006**: 系统 MUST 直接展示真实时间线的素材使用情况，包含采用素材与源区间；
  展示用途的关系不能冒充真实生成输入。
- **FR-007**: 用户 MUST 能建立、重命名、移动和移除项目内逻辑素材文件夹。
- **FR-008**: 用户 MUST 能批量整理素材，并按名称在当前文件夹或整个项目检索。
- **FR-009**: 文件夹操作 MUST 保持素材标识、文件内容、来源记录、剪辑和其他引用不变。
- **FR-010**: 移除非空文件夹 MUST 展示影响预览；确认后保留素材和子目录内容。
- **FR-011**: 用户 MUST 能从已有素材建立角色、场景、道具或声音共享参考入口。
- **FR-012**: 共享参考 MUST 关联可检查的具体素材版本，并支持设置当前版本。
- **FR-013**: 修改参考当前版本 MUST 标出需要复核的使用者，不能改写历史输入或剪辑。
- **FR-014**: 系统 MUST 防止共享参考被移除后留下不可解析的使用者。
- **FR-015**: 用户 MUST 能保存、列出、重命名、实例化及删除自建工作流模板。
- **FR-016**: 模板实例化 MUST 创建独立制作对象，明确显示未绑定参考和不可用模型。
- **FR-017**: 保存模板 MUST 预览可复用内容与素材占位；不保存媒体、凭据、历史输出或任务标识。
- **FR-018**: 所有组织、参考和模板操作 MUST 保持本地，不自动生成、上传或产生费用。
- **FR-019**: 界面和 Agent 入口 MUST 对同一项目提供一致操作和可核实结果，
  拒绝跨项目无效引用，并对冲突、重复重试和部分失败提供可恢复反馈。
- **FR-020**: 原项目 MUST 能继续打开；首次打开不自动移动、删除或重选素材。
- **FR-021**: 首次整理旧项目 MUST 先提供可检查的分组与素材归类预览，再由用户明确应用。
- **FR-022**: 新入口 MUST 可用键盘操作，并有中文和英文文案。
- **FR-023**: 提供已明确分组的八镜隔离示例，证明总览与下钻，不以修改真实影片作为演示。

### Key Entities

- **Asset Folder**: 项目内逻辑目录，包含名称、父目录和素材归属；不代表移动磁盘文件。
- **Reusable Element**: 命名参考，包含用途、说明、版本及其对应素材；不产生新媒体副本。
- **Shot Group**: 命名镜头容器，组织现有节点并保存展开状态；不决定实际生成血缘。
- **Generation / Take**: 一个稳定制作对象及其历史输出；旧结果保持可追踪。
- **Workflow Template**: 可复用的制作结构、可编辑内容与待绑定参考位置；实例之间独立。
- **Timeline Usage**: 对真实采用素材、片段和源区间的只读查看，不是另一套剪辑状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 八镜、至少 140 卡的隔离示例折叠后，总览最多显示八个镜头入口和四个共享入口；
  全部原节点、素材、take 和采用片段仍可恢复定位。
- **SC-002**: 从总览到任意镜头的当前构图、生成配置和采用结果，最多三次明确操作即可到达。
- **SC-003**: 创建目录、批量归类、重命名、移动和移除目录后重新打开项目，结果完全保留；
  所有原素材和剪辑采用均不变。
- **SC-004**: 两个镜头复用同一参考后切换参考版本，两个使用者均可定位；
  已有生成输入与时间线采用的变更数量为零。
- **SC-005**: 同一模板实例化两次后，两套制作对象独立，均可绑定各自参考；
  自动提交任务、上传和付费请求数量均为零。
- **SC-006**: 界面操作与 Agent 操作在重新打开项目后显示相同组织结果；
  旧版本并发写入被拒绝或明确合并，重复重试不创建重复对象。
- **SC-007**: 在隔离示例中完成折叠、展开、查找素材、设置参考、实例化模板的中文与英文验证。

## Assumptions

- 第一版属于单用户、本地项目组织功能；不增加成员权限、团队空间、发布或订阅功能。
- Elements 默认属于当前项目；跨项目复用模板结构可用，但素材必须显式导入或绑定。
- 保留既有组选择、拖动、撤销和重做；新分组能力补足稳定命名、持久化与总览展示。
- 默认不自动猜测旧项目的分镜归属；自动整理如有实现，必须先预览并明确应用。
- 示例沿用上一轮八镜盘点作结构依据，不代表重新确认真实影片内容或人工验收。
- 当前审核只确认用户行为与范围；技术实现、迁移方式和详细性能边界留待 plan 阶段确定。
