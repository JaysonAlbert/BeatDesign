# Feature Specification: 分集、场次导航与跨集共享资产

**Feature Branch**: `codex/canvas-project-organization`（独立特性目录 002）
**Created**: 2026-10-20
**Status**: Draft — 需求与方案待用户审阅；未授权任务拆解或实现
**Input**: 用户：“那就按这个方向，参照Higgsfield的项目和Elements、LibTV的素材板，先用spec-kit把分集、场次导航和跨集共享资产的方案设计出来。”

## 范围与授权

本轮交付需求、研究、技术方案、数据关系、交互与接口约定、验证指南。上述原话授权把需求和方案一起准备供审阅；不把 001 的批准复用为本特性的批准，不开始 tasks、代码、真实影片迁移、生成、合入或部署。

方向：剧集总览 → 分集 → 场次 → 镜头组 → 制作步骤与候选。素材库负责找素材，Elements 负责可复用身份及版本，Canvas 负责局部制作关系，Editor 负责实际剪辑采用。竞品仅是部分交互参考，分集/场次体系是本项目提案。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 找到正确的集与场次 (Priority: P1)

从剧集总览进入分集和场次，在四工作区切换时保留有效范围；已有单片继续直接打开。

**Why this priority**: 先减少导航负担，才能把作品拆成可工作的范围。
**Independent Test**: 三个空白项目组织为三集并创建场次，仅测试导航、刷新、排序即可，无需生成或共享参考。
**Acceptance Scenarios**:

1. **Given** 三集各有三个场次，**When** 进入第 2 集第 3 场并切换四工作区、刷新、后退，**Then** 保留有效范围；剪辑展示本集完整时间线并定位相关片段。
2. **Given** 旧单片与原 URL，**When** 直接打开，**Then** 项目身份、封面、素材、节点、旧 take、剪辑不变。
3. **Given** 不同集有同名场次，**When** 调整集/场次顺序，**Then** 原深链仍定位原对象，剪辑顺序不变。

### User Story 2 - 每次处理一个场次的制作网络 (Priority: P1)

场次拥有独立制作画布，在其中安排镜头组与候选；切换场次不加载整集网络。

**Why this priority**: 仅加筛选不能解决单张画布的容量及连线密度。
**Independent Test**: 独立单片创建三场、各一张画布，无需剧集即可验证切换、保存和组操作。
**Acceptance Scenarios**:

1. **Given** 一集 6 场共 600 卡，**When** 打开 100 卡的场次，**Then** 仅加载该场制作网络，其他场由导航和素材引用可达。
2. **Given** 原有未分类内容，**When** 切换场次，**Then** 内容保留在“项目画布”，不自动搬迁或改写布局。
3. **Given** 转移组到另一场，**When** 预览发现未纳入的依赖或状态冲突，**Then** 说明阻塞原因，整次拒绝且不丢原内容。
4. **Given** 两场使用相同背景，**When** 引用，**Then** 指向同一素材或固定版本，不创建跨画布的虚假连线。

### User Story 3 - 跨集复用固定版本参考 (Priority: P1)

正式角色、场景、道具和声音发布到共享库，各集固定版本引用；新版本由使用方审阅采用。

**Why this priority**: 稳定身份与逐集试验、历史追溯必须兼容。
**Independent Test**: 两个空白分集引用角色 v1，发布 v2，只升级一个消费者，无需真实生成。
**Acceptance Scenarios**:

1. **Given** 两集固定 v1，**When** 发布并推荐 v2，**Then** 提示更新，原输入、历史与剪辑仍不变。
2. **Given** 第一集选择两个制作步骤升级，**When** 确认影响清单，**Then** 仅这两个步骤更新；其余仍为 v1。
3. **Given** 共享参考来自第一集，**When** 第一集移出或归档，**Then** 共享版本与其他集既有引用仍可读且保留来源。
4. **Given** 无共享关系的另一剧集素材，**When** 直接绑定其标识，**Then** 拒绝并要求显式导入。

### User Story 4 - 分类素材板查找、比较与追溯 (Priority: P2)

在现有素材库按本场、本集、剧集共享范围，媒体类型、参考类别、文件夹及用途查找素材；定位准确消费者或历史结果。

**Why this priority**: 素材数量不等于镜头数，找素材无需浏览整张网络。
**Independent Test**: 合成媒体与候选记录即可测试分类、搜索、分页和详情，不需要生成。
**Acceptance Scenarios**:

1. **Given** 共享人物和多批候选，**When** 按角色/图片筛选，**Then** 显示身份、版本、来源与使用情况；详情区分同批结果、历史 take、正式参考。
2. **Given** 500 个以上素材，**When** 翻页及快速改变范围，**Then** 不串集、不混入过期请求，显示已加载数与可核实总数。
3. **Given** 折叠组内旧 take 的搜索结果，**When** 定位，**Then** 打开正确集、场次、步骤详情，保持原布局与采用。
4. **Given** 同一素材被剪辑使用两次，**When** 查看采用，**Then** 显示真实片段及源区间，不由素材或组数量推断镜头数。

### Edge Cases

- 未保存编辑切场：等待保存；失败或冲突保留草稿，允许重试或明确放弃。
- 场次/集被其他窗口归档、移出或改序：显示原因和有效返回入口，不写回修复数据。
- 同名靠稳定身份区分；“叙事场次”与“场景参考”明确分开。
- 更新预览后版本或消费者变化：重新预览；不采用未审阅内容。
- 文件缺失/离线：保留引用来源、阻止相关生成，不静默换版本。
- 移出素材板只解除组织关系；仍被引用的文件不允许物理删除。
- 单场容量满：提示新建另一制作画布，不靠隐藏卡片绕过保存限制。
- 场次改序不重排剪辑，归档不删除其画布、素材或片段。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 支持本地剧集创建、改名、有序分集、归档/恢复，保留独立单片入口。
- **FR-002**: 既有项目最多属于一个剧集并作为一集；加入/移出不改变项目身份或内容。
- **FR-003**: 集内场次有稳定身份、顺序、名称、梗概、归档；允许同名，区分场景参考。
- **FR-004**: 四工作区共享合法范围，深链/刷新/前进后退可恢复；失效时说明并提供返回入口。
- **FR-005**: 场次拥有独立制作画布，切换仅加载所选画布，旧内容保留为项目画布。
- **FR-006**: 场内保留命名组、多组展开、组内整理、组间排列、候选详情，不把候选数当镜头数。
- **FR-007**: 场次顺序、布局、剪辑顺序独立；每集剪辑固定素材及源区间。
- **FR-008**: 跨场转移先预览再显式执行；依赖不完整或冲突整次拒绝，保留媒体与历史。
- **FR-009**: 导航/定位只改变查看范围，不改持久化布局、折叠、输入或采用。
- **FR-010**: 剧集共享素材与 Elements 分开管理；Element 表达角色/场景/道具/声音的身份及版本。
- **FR-011**: 显式发布和使用共享内容，保留来源；复用无需复制文件，未共享素材保持边界。
- **FR-012**: 版本媒体身份不可变；消费者固定版本，发布/推荐新版不改变旧消费者。
- **FR-013**: 升级先展示确切消费者，选择后采用；预览过期或任一目标冲突不部分更新。
- **FR-014**: 升级只改所选未来输入，不改历史、旧 take、剪辑或模板实例原始来源，不自动生成。
- **FR-015**: 归档/移出不破坏已发布版本或引用；在用文件不允许删除，提供恢复与影响清单。
- **FR-016**: 原项目级 Elements/模板保持可用，不静默提升为共享身份。
- **FR-017**: 素材库提供本场/本集/共享范围、媒体/参考类别/目录/用途筛选、分页搜索与准确计数。
- **FR-018**: 详情区分批次结果/历史版本/正式参考/剪辑采用，可定位确切集、场、步骤或片段。
- **FR-019**: UI 与自动化共用归属/版本/冲突/重试规则，重复操作不制造副本，不静默覆盖。
- **FR-020**: 浏览、整理、共享、升级引用不提交任务或上传；生成保留显式预检与提交。
- **FR-021**: 中英文、键盘、可见焦点、窄屏导航可用；导航可收起，保留全幅画布。
- **FR-022**: 迁移先只读预览，旧项目不因打开自动拆场、搬媒体或改封面；真实迁移另需授权。
- **FR-023**: 跨集使用需本集具备受控素材归属；不可伪造地址、其他集标识或模板槽绕过。
- **FR-024**: 明确数量/容量/分页/操作上限，超限可恢复失败不丢内容，不整体加载超大作品节点。

### Key Entities

- **Series**：本地作品集合，有序分集及共享库。
- **Episode**：关联现有项目，独立素材、历史与剪辑。
- **Scene**：集内叙事段落，包含梗概、有序制作画布与镜头组入口。
- **Canvas document**：独立保存及容量的制作网络；项目画布承接旧内容。
- **Shared Element / Version**：稳定身份、不可变媒体版本；推荐与实际固定版本分开。
- **Shared asset relation / Consumer**：共享范围、来源、目标集使用与具体输入/片段，不是媒体副本。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 12 集、每集 20 场的合成作品，从总览最多三次内容选择进入指定场；刷新和前进后退 100% 恢复合法上下文。
- **SC-002**: 共 6,000 卡、单画布不超过 200 卡时，仅加载目标画布；本地热缓存下 95% 切换在 2 秒内可操作，不预载其他场媒体。
- **SC-003**: 20 消费者固定 v1，发布 v2 后 20 个均不变；选 3 个采用后恰好 3 个改变，任一冲突则 0 个改变。
- **SC-004**: 2,000 素材的合成作品，95% 本地热缓存筛选在 1 秒内显示首批；连续 20 次切范围无串集。
- **SC-005**: 兼容/导航/共享/升级验证中既有媒体、历史输入、片段素材和区间 100% 保留，生成提交及上传调用为 0。
- **SC-006**: 四故事在中英文、键盘与窄屏下均能完成；技术检查和用户视觉验收分别记录。

## Assumptions

- 本地单用户；不含团队/RBAC、收费、云同步、审片或发布。
- 每集复用现有 Project，不建每场隐藏项目；单片可有场次而不建剧集。
- 本轮设计包括场次独立画布，不提高单画布 200 卡上限。这是画布身份扩展，不能视作简单侧栏。
- 一场可有多张制作画布；一个画布只属一场或项目未分类区；每集保留一条时间线。
- 不含自动拆镜/分集/排期/生成、整季时间线、季层级、集复制向导或自动批量迁移。
- Elements 首期沿用图像/音频参考；视频作为共享素材。多媒体身份包另案。
- 依赖尚在独立分支的 001 组织功能；本方案不表示它已合入。
- 规模与性能是待验收目标，尚未实测；技术取舍和证据边界见 research.md。
